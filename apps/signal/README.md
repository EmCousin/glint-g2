# Glint Signal

Glint Signal is a private Signal companion for Even G2 glasses. It consists of:

- `plugin/`: a Vite + JavaScript Even Hub plugin for the glasses UI.
- `bridge/`: a token-protected HTTP service intended to run beside a Signal client on your workstation.

The default development flow uses mock conversations. A Gurk provider reads local Signal messages and sends confirmed replies through the existing signal-cli daemon.

## Start locally

Run setup commands from this app directory; npm resolves the monorepo root automatically.

Install dependencies:

```bash
npm install
python3 -m venv bridge/.venv
bridge/.venv/bin/pip install -r bridge/requirements.txt
```

Start the mock bridge, plugin dev server, and simulator together:

```bash
npm run simulate:signal
```

Development uses a local-only default token. The endpoint and token can be configured from Glint Signal's page in the Even mobile app; they are stored locally by Even Hub and take precedence over build-time values. To provide build-time defaults, create local configuration:

```bash
cp bridge/.env.example bridge/.env
cp plugin/.env.example plugin/.env.local
```

Use the same token in both files. The bridge defaults to `http://127.0.0.1:8787`, and the simulator loads the plugin from `http://localhost:5173`. The configured endpoint's origin must still be present in `plugin/app.json`'s network whitelist when the plugin is packaged.

Use a hexadecimal token, such as one generated by `openssl rand -hex 32`. Vite expands `$` sequences in `.env` values, while Node's native env-file loader does not, so shell-style tokens can resolve differently between the plugin and bridge.

## Read from Gurk

Gurk must already be linked and have a local message database. Start the stack with the read-only Gurk provider:

```bash
npm run simulate:signal:gurk
```

The Gurk workflow uses bridge port `8788` and plugin port `5174`, separate from the mock workflow's `8787` and `5173`. Vite uses strict ports so a stale process fails visibly instead of silently opening the wrong plugin.

The provider reads Gurk's config and encrypted database from the standard Linux locations:

- `~/.config/gurk/gurk.toml`
- `~/.local/share/gurk/gurk.sqlite`

Override them with `GURK_CONFIG` and `GURK_DATA_DIR`. Override the SQLCipher executable with `SQLCIPHER_PATH`. The provider requires either `passphrase` in Gurk's config or `GURK_PASSPHRASE` in the bridge environment. It never writes to Gurk's database and does not expose attachments, receipts, or encryption material.

Confirmed replies use the signal-cli daemon socket at `/run/user/$UID/signal-cli/socket`. Override it with `SIGNAL_SOCKET`. When signal-cli has multiple linked accounts, set `SIGNAL_ACCOUNT` to the sending account.

Voice replies capture 16 kHz mono PCM from the G2 microphone and transcribe it locally with Faster Whisper. The default `base` model downloads on the first dictation; override it with `WHISPER_MODEL`, and optionally pin recognition with `WHISPER_LANGUAGE=en` or another language code. Reply drafts expire after one minute, are single-use, and lock both recipient and transcript before confirmation.

The plugin refreshes the active conversation or conversation list every five seconds. The bridge keeps a persistent receive connection to signal-cli and overlays live messages and reactions on Gurk's history, so refresh does not depend on Gurk running. Confirmed replies and reaction changes also appear optimistically. The message action list can add or remove the supported reactions.

Scrolling near the bottom of the conversation list loads older conversations. Scrolling near the oldest visible message loads the next page from Gurk while preserving the current selection.

## G2 controls

- First screen: two conversation cards show the contact, relative date, and latest message; swipe to move the selection and reveal overflow.
- Press a conversation: open its messages.
- In a conversation, two fixed-height message cards are visible in chronological order; swipe to move through the thread.
- Press a message to open the full-screen reader. Swipe to page through the complete body, then press to close it.
- Hold a collapsed message while dictating from the glasses microphone. Partial transcription appears in the inline composer while you speak.
- Hold an open message to show its reaction actions.
- Release to finalize the transcript, review it in the composer, then press to send.
- Swipe while confirming: cancel the reply.
- Double press in a conversation: return to the conversation list.
- Double press from the conversation list: show the system exit dialog.

## Even mobile app

Open Glint Signal from the Even app to see a live representation of the current glasses page and configure the private bridge endpoint and token. The preview uses the same layout descriptors sent to the glasses; device font rendering can differ slightly. The token is stored through Even Hub local storage on the phone, not in a hardware-backed secret store.

## Tailscale

Run the bridge on the workstation's Tailscale address:

```bash
HOST=$(tailscale ip -4) npm run dev:signal:bridge
```

Set `VITE_BRIDGE_URL` in `plugin/.env.local` to the workstation's Tailscale URL or IP. For a packaged build, replace the placeholder origin in `plugin/app.json` with the exact HTTPS origin exposed by Tailscale Serve. Even Hub requires every network origin in the manifest whitelist.

Do not expose the bridge publicly. Tailscale controls network reachability; the bearer token remains required as a second layer.

## Package

After setting the production bridge origin in `plugin/app.json` and `plugin/.env.local`:

```bash
npm run pack:signal
```

This creates `plugin/glint-signal.ehpk`.
